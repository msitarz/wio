# Marked files are Works

## Purpose

wio must find a project's Work contracts wherever they sit in the Works
directory and whatever they are named, and must never mistake another tool's
Markdown file for a Work.

## Intent

Settled with the driver on 2026-11-05. A leaf of `2fh1ar`; planned roots:
`repo`.

- **What a Work is.** Any `.md` file under the Works directory whose metadata
  wio recognizes. It replaces "a directory whose `README.md` has a `wio`
  block".
- **The Works directory** is `[works] dir`, relative to the repository root,
  with `.agents/wio/works` as its default. A path that leaves the repository is
  an error, as root paths already are.
- **The scan** is a fixed recursive walk of `*.md` files that skips
  directories whose names start with `.`. There is no glob setting and no
  `.gitignore` handling: the marker already rules out foreign files, and
  contracts are read from the working tree so that an uncommitted Work is
  found. A glob can be added later without breaking anything.
- **The no-gap rule goes.** A directory between the Works directory and a Work
  need not be a Work; plain directories only group files. How directories
  relate Works is the hierarchy leaf's (`jsymcg`).
- **The marker** is `wio = 1`, the version of the metadata format:
  - required in `+++` front matter, which Hugo and Zola also use (unconfirmed:
    an assumption when this leaf is defined);
  - optional in the `<!-- wio` comment form, which marks itself and implies
    version 1; when present it is checked;
  - an unknown version, such as `2`, or a wrong type, such as `true` or `"1"`,
    is an error naming the versions wio knows, because the file claims to be a
    Work that wio cannot read;
  - `+++` front matter without the marker is silently not a Work. A forgotten
    marker still surfaces: a `depends_on` naming the missing id is an unknown
    id, and the Work is absent from `wio contracts list`.
- **Why a file is not a Work.** `wio contracts show` takes a file path as well
  as an id. For a file that is not a Work it fails and names the reason: no
  metadata block, `+++` front matter without the marker, outside the Works
  directory or under a dot-directory, and the `nesting` reasons the hierarchy
  leaf adds. An id and a path are told apart by a `/` or a `.md` ending.
- **Unchanged:** ids are random Crockford base32 of 6 to 8 characters,
  generated by wio, and two Works with one id are an error. TOML is the only
  metadata language in v0.1; YAML front matter is expected in v0.2 and takes
  the same marker.
- **Open point** for `docs/concepts.md`, not in v0.1: importing existing specs
  as one item: a mode that treats every `.md` file with front matter and an
  `id` as a Work (it needs default actions, which the optional-templates leaf
  `ms5t0t` supplies), configurable id generation, and a looser id format, so
  that ids such as `SPEC-012` are accepted.
