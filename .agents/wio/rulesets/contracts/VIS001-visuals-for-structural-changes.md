Show proportionate before and after diagrams, in a Mermaid type GitHub renders,
for meaningful changes to architecture, module relationships, interactions or
lifecycles, and use before and after prose for tiny changes.

Why: A reviewer judges a structural change much faster from a diagram than from
prose, and a diagram for a tiny change is noise.
