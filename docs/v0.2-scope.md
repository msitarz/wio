# Scope of v0.2 (candidates)

Possible items for v0.2 and later releases, carried over from the v0.1 engine
scope. Concepts are in [concepts](concepts.md) and terms in the
[glossary](../GLOSSARY.md).

## Workflow and history

- `wio next`, and with it reading records from the history (including dropping
  the records of reverted commits) and deciding which results let a gate's next
  stage start.
- The scope check that compares a change with the roots of its Work, which
  needs the record reader.
- Stages, stage presets and rulesets that ship with wio, and skills for
  splitting, reviewing and orchestrating.
- Rules for ad-hoc, non-Work changes: `wio rules list --staged` (or multiple
  `--path` arguments) so an agent can pull the exact rules for its current diff
  without a Work contract.
- Lower-ceremony commit trailers, such as a `prepare-commit-msg` hook recipe or
  helper that appends `Wio-*` trailers without manual copy-paste.
- Session-start and compaction hook recipes for common harnesses (Claude Code,
  Codex, etc.) so `wio context` re-runs automatically after context compaction.

## Onboarding and contracts

- `wio init`, which writes a minimal config with `[works.defaults.actions]`,
  and a named file template as the default for contracts without a template
  ([Open points](concepts.md#15-open-points)).
- `wio contracts adopt`, which adds the marker and a generated id to an
  existing file, and importing existing specs that carry no marker with
  configurable id generation ([Open points](concepts.md#15-open-points)).
- A hierarchy given by a `parent` field, and a config default for the path that
  `wio contracts new` writes ([Open points](concepts.md#15-open-points)).
- `wio contracts list --ids`, plus a filter for missing or stale gate reviews
  so trailer ids do not have to be built by hand.
- Tracking items, sibling splits, joined stage presets, path hints for rules
  inside a root, a reader for git notes, and the setting that rewrites the
  metadata form.
- Memoize rule preset expansion (`expand`) if deep diamond preset graphs ever
  become a performance issue.

## Harnesses and later (v0.3+)

- Checking the documentation of Claude Code, Codex, pi, opencode and Hermes for
  the variables they set for their temp directory and the directories they read
  skills from, to give wio a built-in list of each.
- A lock file for the whole workflow (`wio.lock`, like `uv.lock`: the config,
  templates, selected rules and skills, with hashes), for v0.3 or later; also
  the unit the evaluation harness compares.
- Recipes for harness hooks, a setup wizard, status or ticket connectors, delta
  injection, per-model rules, and the evaluation harness (in its own
  repository).
